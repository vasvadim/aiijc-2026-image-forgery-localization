## 1. Суть задачи

Бинарная **сегментация ИИ-манипуляций на изображениях**. Генеративные модели позволяют делать
малозаметные локальные правки фото (нарисованная царапина на авто, «испорченное» блюдо, поддельный
чек, добавленный/удалённый предмет). Нужно по RGB-изображению найти область, которая была изменена.

- **Вход:** RGB-изображение `H×W×3` (изменённая сцена; изменения могут отсутствовать вовсе).
- **Выход:** маска `H×W×1`, одноканальный PNG, значения строго `0` (фон/оригинал) и `255`
  (изменённая область). Размер маски **обязан совпадать** с размером входного изображения.
- Правки «практически незаметные» — их трудно обнаружить не только людям, но и базовым алгоритмам.
  Это задача класса *image forgery / manipulation localization*, а не обычная семантическая сегментация.

## 2. Метрика — AIC Score (кастомная)

Тестовая выборка содержит два типа изображений:
- **Positive** — в GT есть изменения (маска непустая);
- **Negative** — чистые кадры, GT-маска пустая.

Формулы (воспроизведены с картинки на сайте):

**1. Dice по Positive-примерам:**

```
Dice_pos = (1 / N_pos) * Σ_{i ∈ positive}  2·|P_i ∩ G_i| / (|P_i| + |G_i| + 1e-6)
```
`P_i` — предсказанная бинарная маска, `G_i` — GT-маска, `|·|` — число пикселей.
Считается **per-image, затем усредняется** (не глобальный Dice по всем пикселям).

**2. FPR по Negative-примерам.** Изображение считается ложной тревогой, если площадь
предсказанной маски составляет **≥ 1 % площади кадра**:

```
area_j = |P_j| / (H_j · W_j)
FPR_neg = (1 / N_neg) * Σ_{j ∈ negative}  1[ area_j ≥ 0.01 ]
```

**3. Итоговый AIC Score — гармоническое среднее:**

```
AIC = 2 · Dice_pos · (1 − FPR_neg) / ( Dice_pos + (1 − FPR_neg) )
```

Метрика от 0 до 1. Гармоническое среднее **жёстко штрафует провал любой из двух компонент**:
если FPR_neg = 1 (на всех чистых кадрах срабатываем) — AIC = 0 независимо от Dice.

### Следствия для стратегии (важно)
- Предсказания только бинарные (0/255) → **порог бинаризации подбираем сами на валидации**,
  оптимизируя именно AIC, а не Dice.
- На negative-изображениях достаточно, чтобы маска занимала **< 1 % кадра** — то есть
  небольшой мусор допустим, а вот большие ложные области — нет. Разумный post-processing:
  если суммарная площадь предсказания < порога (например, 1 %), обнулять маску полностью
  (или наоборот — не трогать, т.к. < 1 % и так не считается ложной тревогой; но на positive
  примерах пустая маска даёт Dice = 0). Отдельный **классификатор «есть ли манипуляция»**
  (image-level) + сегментатор — очевидный кандидат для роста метрики.
- Dice per-image означает, что маленькие манипуляции весят столько же, сколько большие; на
  positive-примере пустое предсказание даёт 0, поэтому пропуски дорого стоят.
- Нужно самим написать точный скрипт метрики и валидировать на holdout с реалистичной долей
  negative-примеров (доля в тесте неизвестна — см. открытые вопросы).

## 5. Ограничения (нарушение любого = 0 баллов за весь этап)

1. **Только предоставленные датасеты.** Нельзя брать сторонние данные (CASIA, IMD2020, DEFACTO и т.п.).
   Открытый вопрос — предобученные веса (ImageNet-энкодеры): бейзлайн сам использует
   `encoder_weights='imagenet'`, значит предобученные бэкбоны на практике допустимы. Но использование
   моделей, специально обученных на forgery-датасетах (TruFor, CAT-Net и др.), под вопросом —
   уточнять у организаторов (support@aiijc.com).
2. **≤ 100 GFLOPs на одно изображение.** Считать в строгих FLOPs (1 MAC = 2 FLOPs ⇒ ≈ 50 GMACs).
   `fvcore`, `thop`, `ptflops` выдают MACs под именем «FLOPs» — умножать на 2.
   Эталонный счётчик — `torch.utils.flop_counter.FlopCounterMode`. Он же арбитр в спорных случаях.
   Неясно, на каком разрешении организаторы считают FLOPs (на «одно изображение» — вероятно, при
   том входном размере, который использует наш пайплайн; TTA/ансамбли суммируются!).
3. **Запрет использования теста в обучении**: pseudo-labeling, self-training, любые статистики по
   тесту — запрещено. Тест только для финального инференса.
4. **≤ 50 ms на одно изображение** на инференсе. Проверочная машина: H100 80GB, 1.48 TB RAM,
   Xeon Platinum 8358 (127 ядер). Замер, видимо, включает всю обработку одного изображения;
   ансамбли/TTA нужно укладывать в бюджет.
5. Код обязателен и должен воспроизводить `submission.csv`.

## 6. Критерии оценки (до 13 баллов за этап)

**1. Точность (AIC Score на лидерборде) — 0–10 баллов:** 1 место — 10, 2 — 9, …, 10 место и все
ниже, кто выше бейзлайна — 1 балл; ниже бейзлайна — 0. Равные результаты = равные баллы.

**2. Качество ML-решения — 0–3 балла (экспертиза кода):**
- 0: примитивный пайплайн, нет валидации, дефолтные параметры, нет EDA/предобработки.
- 0.1–1: запускается, но неаккуратно: warnings, нет комментариев, дублирование, нет структуры.
- 1.1–2: хорошо структурирован, полноценный train/val пайплайн, но есть упущения (не зафиксированы
  сиды, только дефолтные геометрические аугментации, нет LR-scheduler / настройки оптимизатора).
- 2.1–3: чистый структурированный код, **EDA**, **пайплайн подбора гиперпараметров и архитектур**,
  **специализированные для задачи методы** (продвинутые аугментации, специфичные loss),

## 9. План работы (черновик, уточнять)

1. Дождаться скачивания, распаковать в `~/aic2026/data/`, проверить md5/целостность.
2. **EDA**: число строк train, доля пустых масок (negative), распределение H×W, площадь масок

   с фиксированным сидом; возможно group-split по оригиналу, если один src порождает много правок).
4. Воспроизвести бейзлайн на кластере → получить локальный AIC и ориентир.
5. Улучшения по приоритету: (а) разрешение 512–768 или тайлинг с учётом лимита FLOPs;
   (б) loss = BCE + Dice/Focal; (в) энкодеры сильнее (EfficientNet/ConvNeXt/SegFormer-MiT) в рамках
   100 GFLOPs и 50 ms; (г) подбор порога + правило по площади под AIC; (д) image-level голова
   «есть манипуляция?» для подавления FPR; (е) псевдо-маски из nanobanana + оригиналы как negative;
   (ж) forgery-специфичные аугментации (JPEG recompress, resize, blur, noise) и, возможно,
   доп. входы (noise residuals / SRM / DCT) — считать их FLOPs тоже.
6. Постоянно измерять FLOPs (`FlopCounterMode`) и latency на A4000 (на H100 будет быстрее ~×3–4,
   но ориентир держать с запасом).
7. Собрать `solution.ipynb` + `README.md` + `submission.zip`, прогнать репликацию с нуля.
