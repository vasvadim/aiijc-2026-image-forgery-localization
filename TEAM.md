## 2. Пути к данным в коде
Единственный способ — переменная окружения:
```bash
export AIC_DATA_DIR=/home/vasilenkova/aic2026/data
```
CSV-файлы датасета содержат относительные пути; корни:
- `$AIC_DATA_DIR/stage1/train.csv` → пути вида `stage1/train/img/...` (относительно `$AIC_DATA_DIR`);
- `$AIC_DATA_DIR/test_stage1/test.csv` → пути вида `test_stage1_img/...` (относительно `$AIC_DATA_DIR/test_stage1`);
- `$AIC_DATA_DIR/nanobanana/pico_nanobanana.csv` → проверить после распаковки.
Абсолютные пути с чьим-то логином в коде запрещены — иначе ноутбук не воспроизведётся у проверяющих.

## 3. Окружение
Одно общее: `~/aic2026/envs/train` (conda из `/opt/miniconda3`, Python 3.11).
```bash
source /opt/miniconda3/etc/profile.d/conda.sh
conda activate /home/vasilenkova/aic2026/envs/train
```
Jupyter-kernel называется **`aic2026`** — выбирать его в VS Code для всех ноутбуков.

Правило: **новые пакеты ставим только через `requirements.txt` в репо** (добавил строку → `pip install -r requirements.txt` → закоммитил). Не делать `pip install <что-то>` руками в общее окружение без записи в файл: второй человек не узнает, а финальный README не воспроизведётся.
Создание/пересоздание окружения: `bash scripts/setup_env.sh`.

## 4. GPU
8× RTX A4000 16 GB, общие с ~120 другими пользователями кластера, **не резервируются**.
- Перед запуском: `bash scripts/gpu_free.sh` — печатает карты по возрастанию занятости.
- Запуск: `CUDA_VISIBLE_DEVICES=<id> python ...` внутри `tmux` (или `nohup ... &`), чтобы обрыв SSH не убил обучение.
- Не занимать больше одной-двух карт одновременно без договорённости в чате команды.
- Не оставлять «висящие» процессы на GPU после окончания: `nvidia-smi` → `kill <pid>`.

## 5. Эксперименты
- Каждый запуск — своя папка `~/aic2026/runs/<логин>/<YYYYMMDD>_<короткое_имя>/` с `config.json`,
  логом, чекпоинтами и `metrics.json` (локальный AIC, Dice_pos, FPR_neg, FLOPs, latency).
- Сводная таблица результатов — `experiments.md` в репо (дата, автор, конфиг, локальный AIC,
  скор на лидерборде если сабмитили, вывод). Заполняем сразу после запуска, не «потом».
- Валидационный split общий и фиксированный (`seed=42`, файл со списком id в репо) — иначе
  результаты двоих несравнимы.
- Скрипт метрики общий (`src/metric.py`) — свои реализации не заводим.

## 6. Сабмиты на платформу
- Перед загрузкой сабмита на aiijc.com — написать в чат команды. Платформа принимает сабмит от
  любого участника, а итоговым считается **последний отмеченный как лучший**, поэтому кто-то один
  отвечает за отметку «Лучшее» (по умолчанию — Вадим).
- В `experiments.md` фиксируем, какой запуск ушёл в сабмит и какой скор получил.

## 7. Ограничения, за которые дают 0 за весь этап (напоминание)
- Только выданные данные (stage1, test_stage1, nanobanana). Никаких сторонних датасетов.
- Тест только для инференса: никакого pseudo-labeling / self-training / статистик по тесту.
- ≤ 100 GFLOPs (строгих, 1 MAC = 2 FLOPs) и ≤ 50 ms на изображение на H100.
- Код (`solution.ipynb` + `README.md`) обязан воспроизводить сабмит без ручных правок.
